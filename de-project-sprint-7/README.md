# Проект Data Lake для соцсети - геоаналитика. 

# Описание
Построение витрин для соцсети на основе событий с геоданными:
- витрина пользователей (user_mart)
- витрина зон (zone_mart)
- витрина рекомендаций друзей (friend_mart)

# Контуры:
# Sandbox (тестовый)
/user/s31894037/data/geo_data_d3_test/ — для быстрой отладки кода, рассчитаны витрины за 3 дня

# analytics (для аналитиков)
/user/s31894037/data/analytics/geo_data_d{depth}/ — итоговые данные
для анализа и BI. Глубина задаётся параметром depth:
- depth=30 → /user/s31894037/data/analytics/geo_data_d30/
- depth=173 → /user/s31894037/data/analytics/geo_data_d173/ (при необходимости)
Параметр depth влияет на диапазон обрабатываемых дат, но не 
формирует имя папки автоматически.

Каждый срез хранится в отдельной папке — это позволяет сравнивать
данные за разные периоды.

Оба контура содержат одинаковые витрины:
user_mart, zone_mart, friend_mart

# Формат данных и партиционирование
Формат - parquet
События: партиционированы по date=YYYY-MM-DD
Витрины user_mart, friend_mart: без партиционирования (снимки текущего состояния)
zone_mart: без партиционирования; колонка month — внутри данных 
(агрегаты по месяцам и неделям)

# Параметры скриптов
Все скрипты параметризованы, что позволяет переключать контуры без изменения кода:
| Параметр         | Пример                                          | Назначение                    |
|------------------|-------------------------------------------------|-------------------------------|
| date             | 2022-01-30                                      | дата отсчёта (конец диапазона)|
| depth            | 3 / 30 / 173 (если понадобится)                 | сколько дней вглубь истории   |
| events_base_path | /user/s31894037/data/geo/events                 | источник событий              |
| geo_base_path    | /user/s31894037/data/geo                        | справочник городов            |
| output_base_path | sandbox: /user/s31894037/data/geo_data_d3_test  | куда помещаем витрины         |
|                  | analytics: /user/s31894037/data/analytics/geo_data_d30|                         |
|                  |(путь передается явно, например: d30 или d173 )  |                               |

Параметризация позволяет переключать контуры без изменения кода.

# Диапазон дат: 
start_date = date - depth + 1 
end_date = date (включительно)
Пример: date=2022-01-30, depth=3 # 2022-01-28, 2022-01-29, 2022-01-30 (3 дня)

# Ограничения и особенности
1.
В geo.csv отсутствует колонка timezone — она добавлена через маппинг по городам.
Исходный файл geo.csv при первом запуске витрин преобразуется функцией prepare_geo():
- lat/lng приводятся к типу double,
- добавляется колонка timezone (маппинг по городам).

Результат кэшируется в /user/s31894037/data/geo/geo.parquet/, и используется всеми витринами.
2.
Исходная ссылка на файл geo.csv при попытке скачать его командным способом отдаёт битый файл (1 строка вместо 24).
Файл восстановлен вручную из материалов курса.
3.
На 30 днях home_city рассчитан у 4 пользователей из 39 639. 
Это - следствие строгого условия (см. Определение home_city в DECISIONS.md). При необходимости — ослабление условия.
Витрины для аналитиков рассчитаны за 30 дней просто для экономии времени и ресурсов. При необходимости можно скачать все данные событий (сейчас  имеем данные за 30 дней, с 2022-01-01 по 2022-01-30 включительно) и рассчитать полные витрины за весь период (173 дня).
4.
Sandbox-контур использует фиксированный путь (geo_data_d3_test/) — это одна песочница для отладки, а не набор срезов. 
Имя папки для аналитиков (analytics) аналогично папкам в 7 спринте (interests_d28, interests_d7). Это позволяет хранить срезы за разные периоды и сравнивать их.

# Рассчитываемые витрины
## Витрина пользователей — user_mart

Назначение: пользователи соцсети с их геолокацией и путешествиями.

Логика:
- act_city — город последнего сообщения;
- home_city — последний город, где пользователь был ≥27 дней;
- travel_* — список и число посещённых городов;
- local_time — время последнего сообщения в таймзоне города.

Колонки:

| Колонка      | Что                                |
|--------------|------------------------------------|
| user_id      | id пользователя                    |
| act_city     | город последнего сообщения         |
| home_city    | домашний город                     |
| travel_count | число посещений                    |
| travel_array | список городов в порядке посещения |
| local_time   | локальное время последнего события |

Подробнее об алгоритме home_city и travel_* — в DECISIONS.md.

## Витрина зон — zone_mart

Назначение: агрегаты событий по городам за неделю и месяц.

Логика:
- для каждого города — счётчики по типам событий (message/reaction/subscription);
- две проекции: недельная и месячная;
- week_user/month_user — по первым сообщениям (регистрации).

Колонки:

| Колонка               | Что                  |
|-----------------------|----------------------|
| month                 | месяц расчёта        |
| week                  | неделя расчёта       |
| zone_id               | id города            |
| week_message          | сообщений за неделю  |
| week_reaction         | реакций за неделю    |
| week_subscription     | подписок за неделю   |
| week_user             | регистраций за неделю|
| month_message         | сообщений за месяц   |
| month_reaction        | реакций за месяц     |
| month_subscription    | подписок за месяц    |
| month_user            | регистраций за месяц |

Подробнее о координатах событий — в DECISIONS.md.

## Витрина рекомендаций друзей — friend_mart

Назначение: пары пользователей для рекомендации дружбы.

Логика: пользователи предложены друг другу, если:
- оба подписаны на один канал;
- раньше не переписывались (за период расчёта);
- находятся ≤1 км друг от друга.

Колонки:

| Колонка        | Что                                   |
|----------------|---------------------------------------|
| user_left      | первый пользователь (меньший user_id) |
| user_right     | второй пользователь (больший user_id) |
| processed_dttm | дата расчёта витрины                  |
| zone_id        | id города (из user_left)              |
| local_time     | локальное время (из user_left)        |


# Запуск
Витрины строятся одним скриптом geo_marts.py, который последовательно
вызывает функции:
- prepare_geo() — подготовка расширенного справочника,
- build_user_mart() — витрина пользователей,
- build_zone_mart() — витрина зон,
- build_friend_mart() — витрина рекомендаций друзей.

Запустить джобу вручную можно (например, из блокнота Jupyter):
--deploy-mode client - для отслеживания ошибок онлайн
--deploy-mode cluster - для отслеживания ошибок на сервере
Тестовый контур
/usr/lib/spark/bin/spark-submit --master yarn --deploy-mode client geo_marts.py 2022-01-30 3 /user/s31894037/data/geo/events /user/s31894037/data/geo /user/s31894037/data/geo_data_d3_test 
Аналитический контур за 30 дней
/usr/lib/spark/bin/spark-submit --master yarn --deploy-mode client geo_marts.py 2022-01-30 30 /user/s31894037/data/geo/events /user/s31894037/data/geo /user/s31894037/data/analytics/geo_data_d30
